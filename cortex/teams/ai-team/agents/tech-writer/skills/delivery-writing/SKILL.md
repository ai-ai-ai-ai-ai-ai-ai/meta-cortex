# Delivery Writing

Delivery guidance describes responsibilities and outcomes. Its technical authority
is the assigned delivery requirement; shared writing guidance owns clarity and links.
The [catalog](index.yaml) identifies this skill's decisions.

## Responsibilities and judgment

- Identify the coordinator, workspace owners, result recipients, and delivery boundaries.
- Keep the Git architecture in [Local Feature Work](../../../../../delivery-team/agents/integration-agent/skills/local-feature/SKILL.md); callers link to it.
- Leave commands, commit organization, conflict handling, and integration strategy to the executing agent within project constraints.
- Describe the result needed for the next decision rather than a fixed command sequence.
- Update callers and catalogs when a responsibility changes.

## Validation

1. Review the ownership, handoffs, and agent discretion against the requested architecture.
2. Check affected links and catalog entries with the existing documentation audit.
3. Report the checks actually run and any unresolved constraints. A prose review does not establish Git execution.
